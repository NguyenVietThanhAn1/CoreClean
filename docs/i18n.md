# i18n Guide

## Overview

CoreClean supports multiple locales via Android resource qualifiers and `AppCompatDelegate.setApplicationLocales()`.

## Structure

```
app/src/main/res/
  values/strings.xml          # Default (Vietnamese)
  values-en/strings.xml       # English
```

## Adding a New Language

1. Create `app/src/main/res/values-<lang-code>/strings.xml`.
2. Copy all entries from `values/strings.xml`.
3. Translate values (keys must stay identical).
4. Add `AppLanguage.<NEW_LANG>` enum entry in `core/preferences/AppPreferences.kt`.
5. Wire the new option in `SettingsScreen` language selector.

## Key Convention

Format: `screen_component_purpose`

Examples:
- `home_card_media_title` — HomeScreen, media card, title text
- `settings_section_theme` — SettingsScreen, theme section header
- `ram_used` — RamScreen, used memory label

## Plurals

Use `<plurals>` for count-dependent strings:

```xml
<plurals name="media_count">
    <item quantity="one">%1$d anh</item>
    <item quantity="other">%1$d anh</item>
</plurals>
```

Access via `resources.getQuantityString(R.plurals.media_count, count, count)`.

## Fallback

- Missing `values-en` key → falls back to `values/` (Vietnamese default).
- Missing `values/` key → compile-time lint warning.
- All keys in `values/strings.xml` are the source of truth.

## Lint

The `values/strings.xml` root element has `tools:ignore="MissingTranslation"` to allow
intentionally untranslated strings (e.g. app name, version strings, debug labels).

## Runtime Locale Switching

Settings → Language → pick locale →  
`AppCompatDelegate.setApplicationLocales(LocaleListCompat.forLanguageTags("vi"))`

This calls `Activity.recreate()` automatically on Android 13+. On lower APIs, the app
will apply the locale on next cold start (AppCompat persists it across restarts).
